# 課題（The Problem）
完成したコードは読める。でも「どう育ったか」は見えない。
- git log を追っても: コミットメッセージだけでは「なぜ」が分からない。
- 完成品から逆算しても: どこが起点でどう分岐したのか、辿る取っ掛かりが掴めない。
- 写経しても: 「その順番で作った理由」が抜け落ちる。

# 仕組み（How it works）
1コミットずつ、意図ごと読み解く。
機械抽出した diff・ファイルツリー・PR に、LLM が書いた解説を重ねる。
- mainline を古い順に: first-parent で辿る一本道を Initial commit から。
- 何を・なぜ・読みどころ: 各コミットに意図の解説。PR や issue を根拠に。
- diff とツリーを並べて: unified / split の diff、変更ファイルツリー、checkout コマンドまで。
