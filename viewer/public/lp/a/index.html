The Problem

完成したコードは読める。でも「どう育ったか」は見えない。

GitHub で最新のコードは読める。けれど、なぜその設計になったのか—— 最初の一歩から積み上がる意思決定の連なりは、履歴に埋もれてしまう。

git log を追っても

コミットメッセージだけでは「なぜ」が分からない。diff を1つずつ開いて文脈を再構成するのは骨が折れる。

完成品から逆算しても

巨大化したコードベースを前に、どこが起点でどう分岐したのか、辿る取っ掛かりが掴めない。

写経しても

手を動かすだけでは「その順番で作った理由」が抜け落ちる。設計判断の連続こそ学びたいのに。

How it works

1コミットずつ、意図ごと読み解く。

機械抽出した diff・ファイルツリー・PR に、LLM が書いた解説を重ねる。 決定的な抽出と、意図の言語化を分離した設計。

mainline を古い順に

first-parent で辿る一本道を Initial commit から。分岐に迷わず、プロジェクトの背骨だけを順番に追える。

何を・なぜ・読みどころ

各コミットに意図の解説。PR や issue を根拠に、変更の狙いと見るべきファイルを言語化。言語固有の概念メモ付き。

diff とツリーを並べて

unified / split の diff、変更ファイルツリー、その時点の checkout コマンドまで。読みながら手元で再現できる。
